# Phase 3 — Evidence and botnet metadata (no PCAP)
Requires Phase 1 and Phase 2. Adds files only. No checkpoint or training changes.

From repository root in PowerShell:

```powershell
$env:PYTHONPATH = "src"
python -m pytest -q tests/test_lab_evidence.py
python -m pytest -q tests test_cic_flow_extractor.py
python scripts/run_demo_evidence.py --csv data/demo/cic_cnn_demo.csv
```

The first script uses the provisional CIC T01 model by default. It runs three mixed cases (BENIGN + PortScan, BENIGN + DoS Hulk, BENIGN + Bot), up to 100 rows per class, and creates a new timestamped directory in outputs/demo_evidence with metrics, confusion matrices, per-class scores, predictions, model provenance and topology lab results. Processing latency is not network detection latency. No data is generated by the test double in production. Once final artifacts are available, repeat using `--model "CIC final seed 42"`. Do not choose a seed based on test metrics. Save each run separately.

The metadata script reads only the existing Friday morning labeled flow CSV from GeneratedLabelledFlows.zip, without extracting any raw packets. It saves source/destination IPs, original timestamps, labels and edge counts. Original timestamp timezone and sub-minute precision are not established; do not infer short beacon periods or convert timestamps to UTC without evidence. A labeled Bot edge is not a verified centralized/P2P topology. These flows may overlap the training dataset, so this is descriptive analysis only. Use a different --out directory for repeat runs.

Controlled topology evidence checks star, cycle and a benign hub (same star geometry); no maliciousness inference. For a verified beaconing evaluation use separately labeled connection events with known timestamp resolution. Linux live packet capture remains separate: Phase 2 captures metadata only, not AI. To meet the original live requirement, validate a live feature producer against the training definitions and run labeled traffic in an authorized isolated lab, then measure alert latency, detection rate and FPR. No PCAP storage is required for that step. CSV replay alone cannot satisfy the live packet requirement.

Validation performed in the build environment: 3 new unit tests passed using a test double; actual Friday morning metadata extraction succeeded (189067 BENIGN, 1966 Bot rows with required non-null fields). Real CIC inference and Linux capture have not been executed for this patch. Expected full local suite: 81 tests if Phase 2's four tests pass and all previous 74 tests remain present.
